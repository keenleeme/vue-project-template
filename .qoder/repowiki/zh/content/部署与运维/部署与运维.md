## Docker镜像构建

本项目采用多阶段构建（multi-stage build）策略，通过两个阶段高效构建轻量级生产镜像。

**构建阶段（builder）**：  
使用 `node:18-alpine` 作为基础镜像，该镜像体积小且适合前端构建。工作目录设为 `/app`，首先复制 `package*.json` 文件并执行 `npm install` 安装依赖。随后复制项目全部源码，运行 `npm run build` 执行构建，生成 `dist` 目录下的静态资源。

**生产阶段（production）**：  
切换至 `nginx:alpine` 镜像，将构建阶段生成的 `/app/dist` 目录复制到 Nginx 默认静态资源路径 `/usr/share/nginx/html/frontend/dist`。暴露 80 端口，并以非守护进程模式启动 Nginx，确保容器持续运行。

该策略有效分离了构建环境与运行环境，显著减小最终镜像体积，提升安全性与部署效率。

## Nginx服务器配置

`nginx.conf` 文件定义了完整的 Web 服务配置，支持静态资源服务、子应用路由及反向代理功能。

**静态资源服务**：  
根路径 `/` 使用 `try_files` 指令实现前端路由的 History 模式支持，确保刷新页面时正确返回 `index.html`。`/assets/` 路径通过 `alias` 指令直接映射到对应目录，提升资源加载效率。

**子应用路由支持**：  
为 Vue2、Vue3、React 和 Angular 子应用分别配置独立的 `location` 块，路径如 `/subapp/vue2`，并设置各自的 `try_files` 规则，确保子应用内部路由正常工作。

**反向代理与API路由**：  
`/api` 路径被代理至后端服务 `http://172.27.0.4:3000`，保留原始请求路径。配置了完整的 WebSocket 支持（通过 `Upgrade` 和 `Connection` 头部），并设置了较长的超时时间（6000秒），适用于长连接场景。同时添加了跨域头（CORS），允许所有来源的请求。

此外，配置了错误页面处理（50x.html）和日志设置，确保服务的健壮性与可观测性。

## 部署脚本执行流程

`deploy.sh` 是一个自动化部署脚本，封装了从备份到启动的完整流程。

**流程概览**：  
1. **初始化**：定义项目名称、部署目录和备份目录。  
2. **创建目录**：使用 `mkdir -p` 创建必要的部署与备份路径。  
3. **备份旧版本**：若 `dist` 目录存在，则复制整个部署目录到备份路径，并以时间戳命名。  
4. **停止旧服务**：进入部署目录，执行 `docker-compose down` 停止并移除旧容器。  
5. **复制新文件**：将当前目录所有文件复制到部署目录，并切换工作目录。  
6. **权限设置**：修改部署目录所有权，避免权限问题。  
7. **文件检查**：验证 `docker-compose.yml`、`Dockerfile`、`nginx.conf`、`dist` 和 `docs` 等关键文件是否存在。  
8. **防火墙配置**：开放 8089 端口（若使用 `firewalld`）。  
9. **启动服务**：执行 `docker-compose up -d --build` 构建镜像并启动容器。  
10. **健康检查**：等待 10 秒后，使用 `curl` 检查主应用是否可访问。若失败则输出日志并退出。  
11. **输出访问信息**：成功后打印主应用及各子应用的访问地址和常用运维命令。

脚本使用 `set -e` 确保任何命令失败时立即退出，保障部署过程的可靠性。

## 多容器编排部署

`docker-compose.yml` 文件定义了单个 Nginx 服务的编排配置，实现容器化部署。

**服务配置**：  
- **镜像**：使用私有仓库 `docker.das-security.cn/nginx:latest` 的 Nginx 镜像。  
- **容器名称**：指定为 `vue-template-nginx`，便于识别与管理。  
- **重启策略**：设置为 `always`，确保容器在异常退出后自动重启。  
- **端口映射**：将宿主机的 8089 端口映射到容器的 80 端口，对外提供服务。  
- **卷挂载**：  
  - 将本地 `nginx.conf` 挂载到容器内的 `/etc/nginx/conf.d/default.conf`，实现配置热更新。  
  - 将本地 `dist` 目录挂载到容器的 `/usr/share/nginx/html`，提供前端静态资源。  
  - 将本地 `docs` 目录挂载到容器的 `/usr/share/nginx/html/docs`，提供文档访问。

该配置通过 Docker Compose 实现了配置与数据的分离，便于在不同环境中快速部署和更新。

## CI/CD集成建议

为实现持续集成与持续部署（CI/CD），建议采用以下流程：

1. **代码提交触发**：在 Git 仓库（如 GitLab/GitHub）中配置 Webhook，当代码推送到特定分支（如 `main`）时触发 CI/CD 流水线。

2. **CI阶段（持续集成）**：  
   - 拉取代码并安装依赖（`npm install`）。  
   - 执行代码格式检查（ESLint）和单元测试。  
   - 运行 `npm run build` 构建生产包。  
   - 将构建产物（`dist` 目录）作为构件（artifacts）保存，供后续部署阶段使用。

3. **CD阶段（持续部署）**：  
   - 将构建产物和部署配置文件（`Dockerfile`、`nginx.conf`、`docker-compose.yml`）传输到目标服务器。  
   - 在服务器上执行 `deploy.sh` 脚本，完成自动化部署。  
   - 可结合 Ansible 或 SSH 命令实现远程执行。

4. **环境管理**：  
   - 为不同环境（开发、测试、生产）维护独立的 `docker-compose` 配置文件或使用环境变量注入。  
   - 使用 `.env` 文件管理敏感配置。

5. **监控与回滚**：  
   - 集成健康检查，部署失败时自动告警。  
   - 保留多个备份版本，支持一键回滚到上一版本。

通过以上流程，可实现从代码提交到生产环境部署的全自动化，大幅提升开发效率与系统稳定性。
