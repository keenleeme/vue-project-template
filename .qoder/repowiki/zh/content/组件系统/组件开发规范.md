## 组件命名约定

组件名称应采用帕斯卡命名法（PascalCase），确保语义清晰且具有唯一性。对于复合功能组件，使用连字符分隔功能模块。

- **基础组件**：`Button`、`Input`、`Card`
- **复合组件**：`HeaderMenus`、`SiderMenus`、`LayoutContent`
- **业务组件**：`BlockCard`、`AlertDetail`、`DrillFilesManager`
- **容器组件**：`Layout`、`Dashboard`、`WorkBench`

组件文件命名与组件名保持一致，文件扩展名为 `.vue`。

## 目录结构规范

组件目录应遵循功能模块化组织原则，采用一致的层级结构：

```
components/
└── moduleName/
    ├── subComponent/
    │   └── index.vue
    ├── comps/
    │   ├── SubComponentA.vue
    │   └── SubComponentB.vue
    └── index.vue
```

- **`comps/`**：存放当前组件的子组件
- **`index.vue`**：主组件入口文件
- **独立功能模块**：每个功能模块单独成目录
- **公共组件**：通用组件放置于 `components/common/` 目录下

## Props类型定义规范

使用 `defineProps` 宏进行类型定义，优先使用 TypeScript 接口或类型别名，确保类型安全和文档可读性。

```vue
<script setup lang="ts">
interface MenuItem {
  children?: MenuItem[]
  [key: string]: any
}

const props = defineProps({
  title: {
    type: String,
    required: true
  },
  more: {
    type: Boolean,
    default: false
  },
  contentPadding: {
    type: [Number, String],
    default: 0
  }
})
</script>
```

**最佳实践：**
- 所有 Props 必须声明类型
- 布尔值 Props 使用 `default: false`
- 复杂类型使用接口定义
- 提供必要的验证规则

## 事件命名规范

事件命名采用 kebab-case（短横线分隔）格式，动词开头，语义明确。使用 `defineEmits` 显式声明事件类型。

```vue
const emit = defineEmits<{
  (e: 'update:modelValue', value: string): void
  (e: 'change', value: string, oldValue: string): void
  (e: 'click', event: MouseEvent): void
}>()
```

**命名规则：**
- `click`、`change`、`input` 等原生事件保持一致
- 自定义事件：`menu-click`、`add-menu`、`save-edit`
- 状态变更：`update:modelValue`、`toggle-drawer`
- 操作事件：`confirm`、`cancel`、`reset`

## 插槽设计原则

插槽设计遵循最小化暴露原则，提供语义化命名插槽，避免过度灵活导致使用复杂。

```vue
<template>
  <div class="block-card">
    <div class="block-card-header">
      <h2>{{ title }}</h2>
      <div class="block-card-description">
        <slot name="description" />
      </div>
      <div class="block-card-ops">
        <slot name="operation" />
      </div>
    </div>
    <div class="block-card-content">
      <slot name="content"><slot />
    </div>
  </div>
</template>
```

**设计原则：**
- 默认插槽用于主要内容
- 具名插槽提供特定位置扩展
- 作用域插槽传递内部数据
- 避免过多插槽导致组件难以维护

## 样式隔离策略

采用 scoped CSS 与 UnoCSS 结合的样式管理策略，实现样式隔离与原子化设计的平衡。

```vue
<style lang="less" scoped>
.block-card {
  background: var(--color-bg-container);
  &.top-border {
    border-top: 1px solid var(--color-component-stroke);
  }
  .block-card-header {
    display: flex;
    align-items: center;
    gap: 12px;
  }
}
</style>
```

**UnoCSS 配置：**
- 在 `uno.config.ts` 中定义设计系统变量
- 使用 CSS 变量实现主题切换
- 原子化类名用于简单样式
- scoped 样式用于复杂组件结构

**最佳实践：**
- 所有组件样式必须 scoped
- 使用 CSS 变量而非硬编码颜色
- 复杂布局使用 scoped 样式
- 简单修饰使用 UnoCSS 类名

## 可访问性支持

组件必须支持基本的可访问性特性，包括ARIA属性、键盘导航和屏幕阅读器兼容。

```vue
<template>
  <a-dropdown class="side-menu-footer-item" placement="bottom">
    <i class="icon-button zq-icon zq-icon-wenben" role="button" aria-label="字体大小" />
    <template #overlay>
      <a-menu @click="handleFontSizeChange" :selected-keys="[themeConfig.fontSize]">
        <a-menu-item key="12px">12px</a-menu-item>
        <a-menu-item key="14px">14px</a-menu-item>
      </a-menu>
    </template>
  </a-dropdown>
</template>
```

**必须支持：**
- 语义化 HTML 标签
- ARIA 属性（`aria-label`、`aria-expanded` 等）
- 键盘导航（Tab、Enter、Space）
- 焦点管理
- 高对比度模式

## 国际化处理

集成 `locale-provider` 实现国际化支持，使用统一的 I18N 命名空间。

```vue
<template>
  <a-button type="primary">{{ $t('I18N.common.add') }}{{ $t('I18N.common.menu') }}</a-button>
  <a-menu-item key="zh">简体中文</a-menu-item>
  <a-menu-item key="en">English</a-menu-item>
</template>

<script setup lang="ts">
import { changeLocale } from '@international/vue3-i18n'

const handleLocaleChangeA = ({ key }) => {
  changeLocale(key)
  window.location.reload()
}
</script>
```

**实现要求：**
- 所有用户可见文本必须国际化
- 使用统一的 I18N 命名空间
- 提供语言切换功能
- 支持动态语言切换
- 在 `locale/index.ts` 中管理语言包

## 组合式API组件开发指南

### 响应式数据管理

使用 `ref` 和 `reactive` 创建响应式数据，合理使用 `computed` 和 `watch`。

```vue
<script setup lang="ts">
import { ref, computed, watchEffect } from 'vue'
import { storeToRefs } from 'pinia'

const appStore = useAppStore()
const { watermark, fullScreen } = storeToRefs(appStore)

const contentPaddingStyle = computed(() => {
  const padding = typeof props.contentPadding === 'number' ? `${props.contentPadding}px` : props.contentPadding
  return padding ? { padding } : undefined
})

watchEffect(() => {
  // 自动响应依赖变化
  menusStore.setActiveRoutes(routes)
})
</script>
```

### 组件通信

- **Props**：父组件向子组件传递数据
- **Emits**：子组件向父组件发送事件
- **Slots**：内容分发
- **Provide/Inject**：跨层级组件通信
- **Pinia**：全局状态管理

## 代码模板与反模式示例

### 推荐代码模板

```vue
<template>
  <div class="component-name" :class="{ 'modifier-class': condition }">
    <slot name="header" />
    <main class="content">
      <slot />
    </main>
    <footer v-if="showFooter" class="footer">
      <slot name="footer" />
    </footer>
  </div>
</template>

<script setup lang="ts">
import { computed, watch } from 'vue'

interface Props {
  modelValue?: string
  disabled?: boolean
  size?: 'small' | 'medium' | 'large'
}

const props = withDefaults(defineProps<Props>(), {
  disabled: false,
  size: 'medium'
})

const emit = defineEmits<{
  (e: 'update:modelValue', value: string): void
  (e: 'change', value: string): void
}>()

const classes = computed(() => ({
  'is-disabled': props.disabled,
  [`size-${props.size}`]: props.size
}))

watch(() => props.modelValue, (newValue) => {
  // 处理值变化
})
</script>

<style lang="less" scoped>
.component-name {
  // 样式定义
}
</style>
```

### 反模式示例

```vue
<!-- ❌ 反模式：未定义类型 -->
<script setup>
const props = defineProps(['title', 'data']) // 缺少类型定义
</script>

<!-- ❌ 反模式：内联复杂逻辑 -->
<template>
  <div>{{ user.permissions.map(p => p.name).join(', ') }}</div> <!-- 模板中不应有复杂表达式 -->
</template>

<!-- ❌ 反模式：未使用scoped样式 -->
<style>
.component { /* 会造成样式污染 */ }
</style>
```
