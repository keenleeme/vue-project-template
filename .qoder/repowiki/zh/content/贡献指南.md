## 开发环境设置
要开始贡献，请确保已安装 Node.js（v16+）和 pnpm。克隆项目后，执行以下命令安装依赖：

```bash
pnpm install
```

项目使用 Vite 作为开发服务器，TypeScript 作为主要语言，UnoCSS 进行原子化样式管理。

## 代码规范
代码规范由 `tsconfig.json` 和 `uno.config.ts` 共同定义。

### TypeScript 配置
`tsconfig.json` 定义了严格的类型检查规则，包括：
- 启用 `strict` 模式
- 禁止隐式 `any`
- 检查未使用的局部变量和参数
- 禁止 switch 语句中的 fallthrough
- 支持 Vue 单文件组件和 JSON 模块导入

路径别名 `@/*` 指向 `src/*`，便于模块导入。

### UnoCSS 配置
`uno.config.ts` 配置了 UnoCSS 的预设和转换器：
- 使用 `presetUno` 和 `presetAttributify` 提供原子化 CSS 支持
- `presetRemToPx` 将 rem 转换为 px，基础字体大小为 4px
- 定义常用快捷类，如 `f-c-c`（居中布局）、`wh-full`（宽高100%）
- 启用指令转换器以支持 `@apply` 等语法

## 提交规范
提交消息必须遵循 Angular 提交规范，由 `commitlint.config.js` 配置：

```js
module.exports = {
  extends: [
    "@commitlint/config-angular"
  ]
};
```

提交类型包括：
- `feat`: 新功能
- `fix`: 修复缺陷
- `docs`: 文档更新
- `style`: 代码格式调整（不影响逻辑）
- `refactor`: 重构（非新增功能或修复）
- `perf`: 性能优化
- `test`: 测试相关
- `build`: 构建系统或依赖变更
- `ci`: CI 配置修改
- `chore`: 其他杂项
- `revert`: 回滚提交

提交格式：`<type>(<scope>): <subject>`

## 分支管理策略
采用 Git 分支管理策略：
- `main` 分支：主分支，保护状态，仅通过 PR 合并
- `dev` 分支：开发分支，集成所有功能
- 功能分支：从 `dev` 分支创建，命名格式 `feature/功能描述`
- 修复分支：从 `main` 分支创建，命名格式 `fix/问题描述`

所有变更必须通过 Pull Request 提交，并经过代码审查。

## 开发脚本说明
`package.json` 中定义了多个开发脚本：

### 主要脚本
- `dev`: 并行启动前端开发服务器和 mock 服务
- `build`: 构建生产版本，使用 `vite.config.prod.ts`
- `lint`: 运行 lint-staged，对暂存文件进行格式化和检查
- `lint-fix`: 手动修复代码风格问题

### 微前端相关脚本
- `start:micro`: 启动所有微前端子应用
- `build:micro`: 构建所有微前端子应用
- `install:*`: 安装各子应用依赖

### 国际化脚本
- `i18n:extract`: 提取国际化文本
- `i18n:translate`: 翻译文本
- `i18n:sync`: 同步翻译

### 格式化与检查
`lint-staged` 配置了不同文件类型的处理流程：
- JavaScript/TypeScript 文件：Prettier 格式化 + ESLint 修复
- Vue 文件：Stylelint + Prettier + ESLint
- CSS/LESS 文件：Stylelint + Prettier

## 运行测试
项目未明确配置测试脚本，但可通过以下方式运行测试：
1. 确保开发服务器运行：`npm run dev`
2. 使用单元测试框架（如 Vitest）编写和运行测试
3. 测试文件建议放在 `tests/` 目录或与源码同级的 `*.test.ts` 文件中

## 提交 Pull Request
1. 确保代码通过所有检查：`npm run lint`
2. 提交符合规范的消息
3. 创建 Pull Request 到 `dev` 分支
4. 描述变更内容和相关问题
5. 等待代码审查和 CI 通过
6. 合并后，变更将集成到下个版本

## 代码质量与一致性
代码质量和一致性是项目长期可维护性的关键。通过以下措施确保：
- 严格的 TypeScript 类型检查
- 统一的代码风格（ESLint + Prettier）
- 原子化 CSS（UnoCSS）避免样式冲突
- 规范的提交消息便于追溯
- 分支保护和代码审查机制

所有贡献者应遵守这些规范，共同维护项目质量。
