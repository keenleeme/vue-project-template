## 简介
本项目采用基于角色和登录状态的动态权限控制机制，通过路由守卫、元字段配置和状态管理实现细粒度的访问控制。系统在用户访问路由时动态校验其权限ID，并结合登录状态决定是否允许访问，确保资源的安全性。

## 权限守卫机制

权限守卫是系统安全的核心组件，负责拦截路由跳转并执行权限验证逻辑。`guard.ts` 文件中的 `setupPermissionGuard` 函数注册了全局前置守卫，对所有路由进行统一控制。

守卫逻辑流程如下：
- 若目标路径在白名单（如登录页、404页）中，则直接放行；
- 若用户已登录，则加载菜单和权限ID（若尚未加载）；
- 根据路由的 `meta.permissionId` 与用户拥有的 `permissionIds` 进行比对，判断是否有权访问；
- 若无权访问且非公开路由（`meta.public`），则跳转至404页面；
- 若未登录，则重定向至登录页。

该机制实现了基于权限ID的细粒度控制，同时支持特殊场景（如钉钉登录回调）的处理。

## 路由配置与权限元信息

路由配置文件 `routes.ts` 定义了所有页面的路径及其权限属性。每个路由通过 `meta` 字段携带权限相关信息，主要包括：

- `permissionId`: 标识该路由所需的功能权限ID，用于与用户权限进行匹配。
- `public`: 布尔值，表示该路由是否为公开访问（无需登录即可访问）。
- `title`: 页面标题，支持国际化。
- `fullScreen`: 是否全屏显示。

例如，`/workBench` 路由需要 `base::workBench:index` 权限ID才能访问，而 `/custom` 路由设置了 `public: true`，允许未登录用户访问。

此外，部分路由使用 `beforeEnter` 钩子实现外部链接跳转功能（如打开新窗口），并阻止原页面跳转。

## 登录状态管理与权限控制关联

登录状态由 Pinia 状态管理库中的 `login` store 统一维护。`src/store/uedModule/login/index.ts` 文件定义了登录配置的状态存储，包括语言、主题模式等信息，并持久化至 `localStorage`。

当用户成功登录后，系统会：
1. 调用 `fetchDingTalkUserInfo` 获取用户信息；
2. 将 `accessToken` 和用户信息存入 `userStore`；
3. 触发权限守卫重新加载菜单和权限ID；
4. 自动同步主题和语言设置（通过 `setTheme` 和 `setI18n`）；

这种设计实现了登录状态与权限数据的联动更新，确保用户在登录后能立即获得对应的界面配置和访问权限。

## 自定义权限逻辑实现指导

若需扩展权限控制逻辑，可参考以下步骤：

1. **新增权限字段**：在路由的 `meta` 中添加自定义字段，如 `roles` 数组，用于基于角色的控制。
2. **扩展用户状态**：在 `userStore` 中增加 `roles` 字段，存储用户角色信息。
3. **修改守卫逻辑**：在 `guard.ts` 中增加角色判断逻辑，优先级可高于或低于权限ID判断。
4. **动态生成路由**：根据用户权限动态生成可访问的路由表，提升安全性。
5. **提供权限指令**：创建 `v-permission` 或 `v-role` 指令，用于控制页面内元素的显示。

示例扩展逻辑：
```ts
if (to.meta.roles && !to.meta.roles.includes(userStore.role)) {
  next('/404');
  return;
}
```

## 安全最佳实践

为保障系统安全，建议遵循以下最佳实践：

### 防止 XSS 攻击
- 对所有用户输入进行转义处理，避免直接插入 HTML；
- 使用现代框架（如 Vue）的默认 DOM 渲染机制，自动防范常见 XSS；
- 设置 CSP（内容安全策略）头，限制脚本来源。

### CSRF 防护
- 使用 HTTPS 传输敏感数据；
- 后端验证 `Origin` 和 `Referer` 头；
- 对关键操作（如修改、删除）采用双重确认或 Token 验证机制；
- 不将敏感 Token 存储在 Cookie 中（本项目使用 localStorage，需防范 XSS 泄露）。

### 其他建议
- 敏感操作日志记录与审计；
- 定期更新依赖库，防止已知漏洞；
- 前端路由仅作为用户体验优化，后端仍需进行权限校验；
- Token 设置合理过期时间，支持自动刷新与强制登出。

## 结论

本系统的权限控制体系结合了路由守卫、元字段配置和状态管理，实现了灵活且安全的访问控制机制。通过 `guard.ts` 的集中校验、`routes.ts` 的声明式权限定义以及 `login store` 的状态同步，构建了完整的安全闭环。开发者可根据业务需求进一步扩展权限模型，同时应持续关注前端安全最佳实践，提升整体系统的安全性。
