# 数据标签模块数据库关系梳理

基于源码分析，梳理数据标签模块中四个核心实体的数据库层面关系。

---

## 一、实体定义

### 1. 数据标签框架 (`tag_framework`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(32) | 主键，如 `f1`、`f2`、`f3` |
| `name` | VARCHAR(100) | 框架名称，如"个人信息安全规范" |
| `source` | ENUM('系统内置','自定义') | 来源，系统内置框架不可删除/编辑 |
| `description` | VARCHAR(500) | 框架描述 |
| `created_at` | DATETIME | 创建时间 |
| `updated_at` | DATETIME | 更新时间 |

### 2. 数据标签分类 (`tag_category`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(32) | 主键，树节点 key，如 `pi-root`、`bank-cust-1` |
| `framework_id` | VARCHAR(32) | **外键 → tag_framework.id**，所属框架 |
| `parent_id` | VARCHAR(32) | **外键 → tag_category.id（自引用）**，父分类 ID，NULL 表示根节点 |
| `title` | VARCHAR(100) | 分类名称，如"个人基本资料"、"客户数据" |
| `default_level` | VARCHAR(20) | 该分类默认分级，如"敏感-3级" |
| `description` | VARCHAR(500) | 分类描述，说明该分类包含的字段示例 |
| `sort_order` | INT | 同级排序 |

### 3. 数据标签分级 (`tag_level`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(32) | 主键 |
| `name` | VARCHAR(20) | 分级名称：未分级 / 一般-1级 / 一般-2级 / 敏感-3级 / 敏感-4级 |
| `sort_order` | INT | 排序，数值越大敏感度越高 |

> **当前实现**：分级是全局共享的枚举（`commonLevelOptions`），所有框架共用同一套分级体系。若未来需要框架独立分级，可加 `framework_id` 外键。

### 4. 数据标签 (`data_tag`)

| 字段 | 类型 | 说明 |
|------|------|------|
| `id` | VARCHAR(32) | 主键，如 `f3-1`、`f1-2` |
| `name` | VARCHAR(100) | 标签名称，如"手机号"、"身份证号" |
| `enabled` | TINYINT(1) | 是否启用 |
| `framework_id` | VARCHAR(32) | **外键 → tag_framework.id** |
| `category_id` | VARCHAR(32) | **外键 → tag_category.id**，所属分类 |
| `level_id` | VARCHAR(32) | **外键 → tag_level.id**，所属分级 |
| `sensitive` | ENUM('是','否','未知') | 是否敏感（可从 level 自动推导，也可手动覆盖） |
| `description` | VARCHAR(500) | 标签描述 |
| `source` | ENUM('用户添加','系统内置') | 来源 |

> **当前实现**：`category` 和 `level` 前端存的是字符串名称而非外键 ID，正式数据库建议规范化为 FK。

## 三、核心关系总结

| 关系 | 类型 | 说明 |
|------|------|------|
| **框架 → 分类** | 1:N | 每个框架包含一棵分类树，分类通过 `framework_id` 归属框架 |
| **分类 → 分类** | 自引用 1:N | 分类通过 `parent_id` 构成树形层级（如"客户数据 → 客户基本信息"） |
| **框架 → 标签** | 1:N | 每个标签必须属于一个框架（`framework_id`），切换框架过滤标签列表 |
| **分类 → 标签** | 1:N | 每个标签属于一个叶子分类（`category_id`），如"手机号"属于"个人基本资料" |
| **分级 → 标签** | 1:N | 每个标签有一个分级（`level_id`），如"敏感-4级" |
| **分级 → 分类** | 弱关联 | 分类节点可设 `default_level`，新增标签时预填默认分级值 |
| **标签.sensitive** | 派生 + 可覆盖 | `sensitive` 根据 `level` 自动推导（含"敏感"→是，未分级→未知，其余→否），但允许用户手动覆盖 |

---

## 四、当前前端代码中的关键约束

1. **框架切换联动**：选不同框架 → 重新加载对应的 `categoryOptions` + 标签列表（`TagPanel.vue` 中 `watch(activeFrameworkId)`）
2. **分类选项来源**：分类下拉选项 `categoryOptions` 需要从分类树提取叶子节点的 `title`；当前 mock 是扁平存的
3. **分级选项共享**：`levelOptions` 目前全局共享 `commonLevelOptions`，与框架无关
4. **sensitive 推导**：`deriveTagSensitive(level)` 在 `mock.ts` 中实现，新增时如未手动指定则自动计算
5. **系统内置保护**：`source='系统内置'` 的框架/标签不可编辑、不可删除

## 五、SQL DDL（参考）

```sql
-- 数据标签框架
CREATE TABLE tag_framework (
    id          VARCHAR(32)  PRIMARY KEY,
    name        VARCHAR(100) NOT NULL,
    source      ENUM('系统内置','自定义') NOT NULL DEFAULT '自定义',
    description VARCHAR(500) DEFAULT '',
    created_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
    updated_at  DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 数据标签分级（全局共享）
CREATE TABLE tag_level (
    id         VARCHAR(32) PRIMARY KEY,
    name       VARCHAR(20) NOT NULL UNIQUE,
    sort_order INT         NOT NULL DEFAULT 0
);

INSERT INTO tag_level (id, name, sort_order) VALUES
('l0', '未分级',   0),
('l1', '一般-1级', 1),
('l2', '一般-2级', 2),
('l3', '敏感-3级', 3),
('l4', '敏感-4级', 4);

-- 数据标签分类（树形结构）
CREATE TABLE tag_category (
    id            VARCHAR(32)  PRIMARY KEY,
    framework_id  VARCHAR(32)  NOT NULL,
    parent_id     VARCHAR(32)  DEFAULT NULL,
    title         VARCHAR(100) NOT NULL,
    default_level VARCHAR(20)  DEFAULT NULL,
    description   VARCHAR(500) DEFAULT '',
    sort_order    INT          NOT NULL DEFAULT 0,

    FOREIGN KEY (framework_id) REFERENCES tag_framework(id) ON DELETE CASCADE,
    FOREIGN KEY (parent_id)    REFERENCES tag_category(id)   ON DELETE CASCADE
);

CREATE INDEX idx_category_framework ON tag_category(framework_id);
CREATE INDEX idx_category_parent    ON tag_category(parent_id);

-- 数据标签
CREATE TABLE data_tag (
    id           VARCHAR(32)  PRIMARY KEY,
    name         VARCHAR(100) NOT NULL,
    enabled      TINYINT(1)   NOT NULL DEFAULT 1,
    framework_id VARCHAR(32)  NOT NULL,
    category_id  VARCHAR(32)  NOT NULL,
    level_id     VARCHAR(32)  NOT NULL,
    sensitive    ENUM('是','否','未知') NOT NULL DEFAULT '未知',
    description  VARCHAR(500) DEFAULT '',
    source       ENUM('用户添加','系统内置') NOT NULL DEFAULT '用户添加',

    FOREIGN KEY (framework_id) REFERENCES tag_framework(id) ON DELETE CASCADE,
    FOREIGN KEY (category_id)  REFERENCES tag_category(id)  ON DELETE RESTRICT,
    FOREIGN KEY (level_id)     REFERENCES tag_level(id)     ON DELETE RESTRICT
);

CREATE INDEX idx_tag_framework ON data_tag(framework_id);
CREATE INDEX idx_tag_category  ON data_tag(category_id);
CREATE INDEX idx_tag_level     ON data_tag(level_id);
CREATE INDEX idx_tag_enabled   ON data_tag(enabled);
```
